# sliplib

Rust crates shared by the slipmesh components: the Talos extension daemons and their config
generator, the RouterOS tool and the Kubernetes operators.

| crate | what it gives |
| --- | --- |
| [`sliplib-secrets`](secrets) | WireGuard keys: decoding, generation, the public key, and a private key that never prints |

The crates are one workspace with one version and one tag. A change to one crate moves the tag for
all of them; for a consumer of another crate that update changes nothing.

## Using a crate

Depend on the crates you need by git tag; nothing is published to crates.io:

```toml
[dependencies]
sliplib-secrets = { git = "https://github.com/slipmesh/sliplib", tag = "v0.1.0" }
```

### `sliplib-secrets`

A key is the base64 text of 32 bytes, the form configs and RouterOS carry it in. `PrivateKey` keeps
that text as given, so it is written back unchanged, and prints as `<redacted>` through `Debug`:
a structure that holds one can be logged or shown in a diff without leaking it. The text leaves
through `expose()`, and through serde into the config it is written to.

```rust
use sliplib_secrets::wireguard::{PrivateKey, decode_key};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let key = PrivateKey::generate();
    let public = key.public_key()?;
    let bytes: [u8; 32] = decode_key(&public)?;
    assert_eq!(format!("{key:?}"), "<redacted>");
    println!("{public} is {} bytes", bytes.len());
    Ok(())
}
```

`is_same_key` compares two private keys as WireGuard uses them: RouterOS returns a key in the
clamped form X25519 reduces it to, which differs as text from the key as generated.

## Development

```bash
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
```

CI runs the same on every pull request and push, for the x86-64 and arm64 musl targets, and
`cargo audit`, which also runs weekly. Code style: [docs/CODESTYLE.md](docs/CODESTYLE.md).

Before a pull request, two more checks run locally; they take longer than CI should:

```bash
cargo mutants
cargo +nightly fuzz run decode_key -- -max_total_time=300
```

[`cargo-mutants`](https://mutants.rs) changes the code one place at a time and expects a test to
fail each time; [`.cargo/mutants.toml`](.cargo/mutants.toml) lists what it skips and why.
[`cargo-fuzz`](https://github.com/rust-fuzz/cargo-fuzz) runs the targets in
[`fuzz/fuzz_targets`](fuzz/fuzz_targets), each for five minutes; `cargo +nightly fuzz list` names them.

## Releasing

Releases come from `main` only. Run the Release PR workflow, with the version or empty to compute it
from the conventional commits since the last tag:

```bash
gh workflow run release-pr.yml -f version=v0.1.0
```

It opens `chore: release vX.Y.Z` with the workspace version moved and `CHANGELOG.md` regenerated by
git-cliff. Merging it tags the merge commit and creates the GitHub Release from that changelog
section; consumers then move their tag.
